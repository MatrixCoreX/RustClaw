The Model Context Protocol (MCP) lets the agent use tools from other systems. For example, an order server can return the current shipping status, carrier, and tracking number.

Add a local or remote MCP server

In the admin console, open Models → External tool servers → Add server. Give each server a unique name and fill in the connection details provided by that server.

Local command (stdio)
Enter the startup command and its arguments, one argument per line. The command runs on the device hosting the agent, so use paths that exist on that device.
Remote server (Streamable HTTP)
Enter the full MCP endpoint URL, such as https://tools.example.com/mcp. If the server requires authentication, select its authentication method. Enter the environment variable name in credential fields and set its value on the service host.

Choose which tools the agent can call

  1. Review the server details and mark it as trusted if you manage it or trust its operator.
  2. In Allowed tools, enter each exact tool name from the server on its own line. For this walkthrough, allow the read-only order lookup tool supplied by your server.
  3. Enable the server and turn on Enable MCP tools. Select Save MCP settings and restart the service if prompted.

Test the connection, then look up an order

Once the server shows Ready, select Test protocol. Confirm that the tool list includes your lookup tool, then send a request in Agent chat.

“Where is order 3? What is its tracking number?”

Use an order that exists in your test system. Compare the status and tracking number in the reply with the record from the order system.

When the server or tool is unavailable

The server shows Pending restart
Restart the agent service, then refresh the server status.
The server is Ready and the tool list is empty
Check that the server exposes the tool names in Allowed tools. Match the names exactly and put one on each line.
The connection test fails
Check the local command or remote endpoint from the agent host. For an authenticated server, verify the expected environment variables are available to the service.
