用 $brand 的 MCP 与 RAG 回答订单售后问题

客户常在同一条消息里问两件事，比如订单现在在哪、商品有质量问题时谁承担退货运费。这个演示把订单服务和售后手册接入同一个 Agent，再用一次提问核对物流结果与手册出处。

准备两种来源 发送一条售后问题 核对答案 排查漏查

接入模拟订单，导入演示售后手册

  1. 配置只读 MCP 订单服务。先查订单 3，确认物流状态是在运输，单号为 7898047967。
  2. 下载并导入演示《售后手册》。把库名设为售后手册，在「记忆管理 → 知识库」搜索「退货运费」，确认能找到第 3.2 节的原文。

用一句话同时查询订单和退货规则

在 Agent 对话里发下面这条消息。「客服已核实」是这次演示给出的条件。物流状态由订单服务提供，退货运费规则来自手册。

「帮我查一下订单 3 现在到哪儿了，给我快递单号。如果客服已确认商品有质量问题，寄回去的运费谁承担？请查《售后手册》并注明章节。」

分别核对物流结果和政策出处

订单物流
订单 3 正在运输，当前在杭州转运中心，快递单号为 7898047967。
退货运费
客服核实商品有质量问题后，由商家承担退货运费，出处是《售后手册》第 3.2 节「质量问题退货」。

还可以追问「只根据《售后手册》，仓库签收后几天内发起退款？」演示手册没有规定这一时限，回答应说明资料未提及。

Agent 只回答了其中一部分怎么办

有售后规则，缺订单结果
先完成 MCP 连接与工具测试，再单独查订单 3，确认查询工具可用。
有订单结果，缺手册出处
打开 知识库导入与检索步骤，核对库名，确认搜索能命中「退货运费」。再请 Agent 写出文件名和章节。
