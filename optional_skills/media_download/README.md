# media_download

Python bundled on-demand skill adapter for the local media tools originally supplied from `/home/guagua/media_download` at commit `51db27f`. The bundled copy removes product-coupled runtime-path discovery and relies on neutral environment variables or `PATH` instead.

The package implements `agent-jsonl-v1` and exposes structured `capabilities`, `download`, `resolve`, `ocr`, and `prepare_x` actions. It supports Douyin, Kuaishou, Xiaohongshu, TikTok, YouTube, and WeChat Channels. WeChat Channels uses a user-authorized Tencent Yuanbao session stored only in `browser-profile/wechat_channels`; a missing or expired session opens the official login page and resumes the same task after login. Douyin, Xiaohongshu, and WeChat Channels image-article posts attempt the platform-provided article and every original image independently: all successfully retrieved components are delivered, and an unavailable sibling component does not suppress them. Available article text is returned inline and as a UTF-8 text artifact. Video/audio transcription is handled by the host-selected STT capability after download. OCR of text inside images remains explicit, merges multiple inputs into one ordered document without per-image source labels, and uses the same dual text delivery contract. It bundles only the required Python sources; historical downloads, virtual environments, caches, and the browser UI are intentionally excluded.

The adapter always disables system-browser cookie import. Generated files default to the runtime-provided task artifact directory. Skill Store installation prepares the declared Python environment and host-approved FFmpeg, Tesseract, and Chromium tools. Local speech recognition remains isolated in the optional `local_asr` skill.

Douyin and Xiaohongshu profile downloads use stable platform item IDs and the host-provided private skill-storage directory for resumable checkpoints. Each progress transition creates an immutable partial manifest plus content-addressed verified blobs. A safe retry restores completed work without downloading it again, and a separate complete manifest is written only after every current item verifies. These checkpoints do not modify tracked configuration or share storage with other skills.
