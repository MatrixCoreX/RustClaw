# 桌面本地资产账户实施记录

日期：2026-09-11。版本：0.3.0。按最新要求调整为：先完成桌面，再将后端改进交给后端 agent。桌面实现和隔离协议测试已完成；真实资产服务联调等待后端实现。

后端 agent 请直接阅读：[独立资产账户后端实施交接](asset-owner-backend-handoff-20260911.md)。其中的 API 是已落地桌面客户端的目标合同，不代表现有设备已经提供这些接口。

## 1. 已完成范围

- 桌面首页提供“本地资产账号”入口，离线也能创建账户。
- 独立本地安全窗口设置密钥库密码、生成 K1/secp256k1 密钥对、管理多个账号、锁定、加密备份和恢复。页面与 IPC 结果不包含私钥。
- 资产/Bancor 页面统一选择“硬件设备绑定账号”或“桌面本地账号”；切换不会修改硬件绑定和奖励配置。
- 本地账户余额、分页记录、AIC/USD 转账、Bancor 买入/卖出、来源节点及账本展示已接入新协议。
- 资金操作必须在独立窗口核对完整账户、收款方、金额、费用、最低收到、节点、账本与有效期后确认。原生层校验并签名，禁止普通页面任意签名。
- 提交前持久化本机操作 ID；响应丢失保留待核实状态，阻止同账户同账本的新资金操作，并通过只读签名查询原操作结果。不自动重发资金请求。
- 旧后端未实现 capabilities 时明确提示后端需要升级，余额显示未同步，不伪造为零、不转用硬件账户。
- 全部功能、依赖、测试、文档位于 `desktop/`，没有修改服务端、共享 `UI/`、设备配置或真实资产。

首版仅覆盖资产展示、Bancor 买卖、转账。不增加 NNI 加入/解绑、奖励、心跳、通用链钱包、助记词、明文私钥导入导出、云同步和自动交易。账户改名/归档/删除、密钥库改密码不包含在 0.3.0。

## 2. 密钥保护实现

| 项目 | 实现 |
| --- | --- |
| 密钥与随机性 | OS 随机源；有效 secp256k1 scalar；压缩 K1 公钥和既有校验和编码 |
| 数据加密 | 随机 32 字节主密钥；XChaCha20-Poly1305；随机 24 字节 nonce；AAD 绑定版本、库 ID 和账户元数据 |
| 密码包装 | Argon2id v0x13，64 MiB、3 次、4 路、32 字节输出；16 字节随机 salt；参数固定在格式 v1 |
| 系统存储 | 原生系统凭据库只保存密码加密过的主密钥包装；密码和明文私钥不持久化；不可用时拒绝初始化/解锁，无明文 fallback |
| 文件 | 用户应用数据目录中的 `asset-wallet/`；Unix 目录 0700、文件 0600；临时文件、sync、原子替换；库文件进程锁 |
| 内存 | 原生私钥/解密缓冲区/密码使用 zeroize 容器；不通过 IPC 向 WebView 返回私钥或签名 |
| 解锁 | 启动锁定；密码操作后冷却 2 秒；后台查询不会延长解锁；最多 5 分钟自动过期，创建/备份等显式密钥库操作会重新计时 |
| 生命周期 | 离开主窗口和安全窗口后锁定；Ubuntu 查询 logind 锁屏状态；定时器检测运行中断；断开设备/登录切换撤销待确认操作 |
| 备份 | `asset-account-backup-v1`；独立密码、salt、nonce；公钥绑定认证加密；原生文件选择器保存后读回解密验证，才标记备份完成 |
| 恢复 | 校验格式、长度、公私钥一致性和重复账户；重新加密进新电脑的密钥库，不依赖原电脑系统凭据库 |

系统文件选择窗口打开期间，不根据窗口失焦锁定；5 分钟到期与系统锁屏检查仍生效。

库最多保存 100 个账户。签名要求该账号已验证加密备份。本机最多保留 500 条操作摘要，满额时只淘汰已结束摘要，不删除待核实记录。远端记录不受此本地摘要数量影响。

安全边界：这不是硬件钱包；无法保证抵御已控制当前 OS 用户的恶意程序。未实现专用防交换内存/崩溃转储策略。Windows 当前使用用户应用目录继承 ACL；Windows/macOS 原生密钥库、系统锁屏/休眠、安装与跨系统恢复仍需各自实测，不能由 Ubuntu 测试代替。没有备份或遗失备份密码时，不承诺重置后找回私钥。

## 3. 桌面工程与协议

- `src/wallet/`：加密、密钥、系统凭据库、文件、备份、状态、窗口命令和生命周期。
- `src/asset_operations/`：严格 typed API、原始 challenge 校验、原生确认、签名、提交与结果核实。
- `frontend/wallet/`：账户管理与确认窗口、账户选择、资产和 Bancor 专属页面；复用原有 CandleChart。
- `scripts/shared-ui-adapter.ts`：只在桌面构建中替换两页组件引用，浏览器源码保持原样。
- `capabilities/wallet.json`：安全窗口专用白名单。主窗口不能初始化/解锁/生成/导出/确认；安全窗口不能使用主控制台通用请求或文件 API；AiAPP 无密钥库权限。
- `tests/fixtures/asset-owner-v1-vectors.json`：固定公开测试密钥的签名字节向量；仅供测试，不可充值。

所有网络操作复用当前设备 profile 的可信连接、管理员登录、Cookie/CSRF 和撤销机制。新接口不接受任意签名字符串；原生层从固定路径取回结构化 challenge，校验操作、账户、账本、节点、金额、费用、收款方、期限等，再对原始 UTF-8 字节进行一次 SHA-256 的 low-S ECDSA 签名。

真正的资产所有权、原子扣款、防重放、幂等及账本状态由后端负责。桌面已经做好客户端约束，但不能通过仅修改客户端替代这些服务端保证。
