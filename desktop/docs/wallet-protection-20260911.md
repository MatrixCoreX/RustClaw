# 桌面密钥保护 0.4.0

本轮实施方案 1、2、5，只修改 `desktop/`。发行目标是 Linux/Ubuntu x86_64；现有账户公钥、K1 签名合同和后端 API 不变。

## 账号和迁移

每个账号使用独立随机 32 字节数据密钥与 XChaCha20-Poly1305 密文。主密钥包装数据密钥，并认证整个公开目录、账号 ID、公钥、名称、备份状态及所有账号密文。数据密钥和私钥的 AAD 分别绑定密钥库 ID、账号 ID、公钥与用途，不能跨账号替换。

普通解锁只验证目录，不解密全部私钥。签名、备份只打开所选账号；创建、恢复账号保留其他账号的密文。系统凭据库仍保存密码加密的主密钥包装记录，密码 KDF 保留原 v1 参数以兼容已有凭据。

旧密钥库在首次正确解锁时升级：解密、校验全部旧账号，构造独立密文，逐个读回比对，再验证新目录，通过原子文件替换发布。沿用 `vault-v1.json` 路径，文件内部版本变为 2；密码错误或发布前失败不替换旧文件。持久化完成后不保留额外的旧库副本。替换后的目录同步失败可能报告存储错误，但磁盘上仍是完整的旧版或新版文档，重新打开可继续读取。账号 ID、公钥、私钥和已备份状态不变。

界面在第一次解锁前说明升级。旧桌面版本不能读取升级后的本地文件；已有 v1 加密备份仍可恢复。安装本身不解锁、迁移或读取真实私钥。

## 独立密钥进程

GUI 只持有进程客户端。当前可执行文件在内部 worker 模式进入密钥循环，先应用系统保护，再读取账号文件和系统凭据，不初始化 Tauri 或创建 WebView。程序仍链接 GUI 动态库，不能据此声称已经剥离全部 GUI 库的攻击面。

仅通过父子匿名管道传递类型化请求，帧上限 128 KiB，协议版本和单调请求序号严格校验；只提供初始化、锁定、解锁、公开账号、生成、加密导入导出和合同签名。没有通用“导出明文私钥”或任意字节签名接口。签名进程再次检查账号、节点、账本、金额、费用、有效期和用户意图，只返回签名；GUI 继续负责可信确认窗口、节点认证、账户选择代次与交易提交。

管道读写有超时；父进程对通信异常停止并回收 worker，禁止自动重放签名操作。worker 收到畸形、重复序号、超大或截断帧后退出。父进程意外退出由内核结束 worker。固定五分钟期限、系统休眠/时钟异常、应用失焦和安全窗口关闭继续锁定；界面状态轮询不能吞掉需要撤销确认的锁定事件。每笔签名仍要求重新输入密码，并在成功或失败后锁定。

## 不同系统的适配和发布状态

| 平台 | 本轮实现/状态 | 后续平台优化要求 |
| --- | --- | --- |
| Linux x86_64 | Secret Service；`mlock`、保护页、`MADV_DONTDUMP`；禁止 core dump；`no_new_privs`；seccomp TSYNC；父进程死亡终止；关闭继承的非管道 FD | 本机 Ubuntu 原生验收；其他发行版和内核仍需安装测试 |
| Linux aarch64 | 相同 adapter，BPF 使用 aarch64 系统调用和审计架构 | 需要 ARM 实机验证、打包和资源测试；本轮不发布 ARM 包 |
| macOS | Unix 锁页分支可编译；新版密钥进程返回结构化不支持错误，不进入无隔离模式 | 单独签名 helper/XPC、Keychain 权限、Hardened Runtime、适合 helper 的 App Sandbox、锁屏/休眠和退出回收；Apple Silicon/Intel 原生验证 |
| Windows | 新版密钥内存/进程 adapter 未实现；返回结构化不支持错误 | VirtualAlloc/VirtualLock 与保护页、用户专属 ACL、Credential Manager、受限令牌/Job Object、受控 IPC、锁屏/休眠、安装与原生验证 |

加密算法、密文格式和备份参数跨平台保持统一，后续系统 adapter 不能改变公钥或签名合同。本轮不发布 Windows/macOS 新包。跨平台静态门禁与 Apple target 编译尝试记录在验收目录；交叉检查不等于原生安全验收。

Linux worker 允许 Secret Service 所需的 AF_UNIX 本地 IPC，禁止创建 IP、netlink、packet socket，禁止 exec、创建子进程、ptrace、process_vm、mount、BPF、perf、userfaultfd 和 io_uring。允许受约束的线程创建，过滤器同步到所有线程。启动后验证过滤器、不可转储和网络拒绝状态，无法提供保护即停止。需要支持 `close_range` 的内核；本轮安装包已有 GLIBC 2.39+ 依赖。

这不是完整文件系统沙箱：worker 仍以当前用户权限读写账号和用户选中的备份；本地 IPC 也不等于可证明的全部外传通道隔离。它没有 WebView、HTTP 客户端调用或网络交易提交职责。

## 内存边界

主密钥、账号数据密钥、解密后的私钥和解密文档使用独占匿名映射、不可访问的前后保护页和强制锁页。Linux 排除这些页面的转储；释放前擦除整个可写区，清零后解除锁页并撤销映射。锁页或平台保护失败不会转为普通堆内存保存密钥。

Argon2 计算工作区显式分配并在所有正常返回/错误路径清零；库的 `zeroize` 特性本身不会清理完整工作区。旧库迁移的 serde 条目暂存区会在退出时清零，但没有锁页；这是一次性兼容路径。64/256 MiB 的计算工作区没有锁页，普通用户锁页额度不足以覆盖它。密码的 WebView/JSON/强度检测库临时副本、密码派生计算区、编译器和密码学库内部临时副本、栈、寄存器、内核管道及系统休眠文件不受“全部锁页/可证明清除”保证。进程崩溃不能保证执行清理。不能声称可抵御内核/管理员控制、用户输入被截获、磁盘旧块恢复或硬件侧信道。

## 备份 v2

新备份要求独立密码：16–128 个 Unicode 字符、最多 512 字节、无控制字符，与密钥库密码不同；本地 `zxcvbn` 强度检查达到 4 分。它会检查常见密码、重复/连续模式以及账号名称和公钥；这属于猜测成本估计，不是强密码的数学保证。

格式为 `asset-account-backup-v2`，XChaCha20-Poly1305 加密原始 32 字节私钥。Argon2id v19 固定参数为 262144 KiB、3 次、4 lanes、32 字节输出，随机 16 字节盐与 24 字节 nonce。格式、公钥、cipher 和完整 KDF 描述都纳入 AAD。只接受明确支持的参数组合，不执行文件指定的任意成本，也不降级到旧参数。

备份输入上限 16 KiB，拒绝重复/未知字段、错误长度和不支持参数。导出后实际读回、解密并比较原公钥和私钥，通过后才记录新版备份状态。密码派生与验证在独立进程执行，界面显示正在处理。

v1 备份保持只读恢复兼容（原 Argon2id 64 MiB、3 次、4 lanes），不对旧密码追加强度门槛。恢复或迁移的旧备份账号提示重新导出；不会修改原备份，也不会自动上传。新版备份与新密码不能让已流出的旧备份失效；备份持有人仍可离线猜测密码，应用的输入限速对此无效。

## 验收

证据目录：`desktop/test-results/wallet-protection-0.4.0/`。覆盖旧库迁移及发布前失败、账号隔离、AEAD 元数据/密文篡改、弱密码、v1/v2 恢复、恶意参数、文件权限/链接、进程系统调用与内存保护、真实 Secret Service、父进程退出以及原生资产/Bancor/转账/多语言回归。最终数量和安装校验以该目录验收 JSON 为准。

这些是本仓库自动化和本机原生测试，不是独立第三方安全审计。测试仅使用临时账号、隔离凭据库和测试交易服务。

依据：[RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html)、[OWASP 密码建议](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)、[Linux mlock](https://man7.org/linux/man-pages/man2/mlock.2.html)、[Linux dumpable](https://man7.org/linux/man-pages/man2/PR_SET_DUMPABLE.2const.html)、[Linux seccomp](https://man7.org/linux/man-pages/man2/seccomp.2.html)。256 MiB 是本客户端选用的增强参数，不应写成 RFC 的原样推荐配置。
